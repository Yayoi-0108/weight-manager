# Google Play 出品準備ガイド

最終確認日: 2026年9月29日

この文書は、`Yayoi-0108/weight-manager` を将来AndroidアプリとしてGoogle Playへ出品する場合に備え、設計上の注意点と必要な手続きを整理したものです。

現時点でGoogle Playへの出品を直ちに行うことを前提とせず、iOS対応時にAndroid展開を難しくする構成を避けるための資料として使用します。

## 1. 基本方針

現在のHTML、CSS、JavaScriptを共通資産として維持し、CapacitorなどからiOSとAndroidの各ネイティブプロジェクトを生成できる構成を推奨します。

```text
weight-manager
├── 共通Web資産
├── iOSプロジェクト
└── Androidプロジェクト
```

体重、BMI、グラフ、カレンダー、バックアップ形式などの主要ロジックは共通化し、次の機能だけをOS別のネイティブ機能として扱います。

- データの永続保存
- ファイルの保存と読み込み
- 共有シート
- ローカル通知
- 権限管理
- 外部リンクの表示

## 2. 現在から守る設計ルール

- [ ] iOS専用APIをWeb側の主要ロジックへ直接埋め込まない
- [ ] OS別処理を小さなアダプターまたはサービスに分離する
- [ ] iOSとAndroidで同じJSONバックアップ形式を使用する
- [ ] 日付は端末のローカル日付として扱う方針を統一する
- [ ] 小数点、単位、タイムゾーンの扱いを共通化する
- [ ] プライバシーポリシーの基本内容を両ストアで共通化する
- [ ] 通知を拒否しても主要機能を利用できるようにする
- [ ] 必要最小限のOS権限だけを要求する
- [ ] CDN上のスクリプトではなく、アプリ内に依存ファイルを同梱する
- [ ] Web版、iOS版、Android版のデータ形式にバージョン番号を付ける

## 3. Google Play出品に必要なもの

### アカウント

- [ ] Google Account
- [ ] Android Developer ConsoleまたはGoogle Play Consoleの開発者アカウント
- [ ] 本人確認に必要な身分証明書や連絡先
- [ ] 支払い方法
- [ ] 公開する開発者情報

一般公開を行うフル配布アカウントには、1回限り25米ドルの登録料が必要です。組織アカウントではD-U-N-S Numberと組織Webサイトなどが求められます。

登録制度は変更される可能性があるため、実際の登録時に最新の案内を確認します。

### 開発環境

- [ ] Android Studio
- [ ] Android SDK
- [ ] Java Development Kit
- [ ] Android実機またはエミュレーター
- [ ] リリース用の署名鍵

Androidアプリの開発とGoogle Playへの提出はWindows環境でも行えます。

## 4. Androidアプリの識別情報

次の情報を出品前に決定します。

| 項目 | 候補・説明 |
| --- | --- |
| アプリ名 | `体重管理`。Google Play上での表示名 |
| Package name | 例: `com.yayoi0108.weightmanager` |
| Version name | 初回は `1.0.0` を候補とする |
| Version code | 初回は `1`。公開ビルドごとに増やす |
| カテゴリ | 健康＆フィットネスを第一候補とする |
| 価格 | 無料を第一候補とする |
| 配信形式 | Android App Bundle（AAB） |

Package nameは公開後に変更できない重要な識別子です。iOSのBundle IDと文字列を揃えると管理しやすくなりますが、両者は別の識別情報です。

## 5. Androidの技術要件

2026年8月31日以降、新規アプリとアップデートはAndroid 16、API level 36以降を対象にする必要があります。

実装開始時と提出直前に、次を確認します。

- [ ] 必須のtarget API level
- [ ] Android Gradle Pluginの対応バージョン
- [ ] Capacitorおよび使用プラグインの対応状況
- [ ] 64ビットABIへの対応
- [ ] App Bundleの署名とPlay App Signing
- [ ] Androidのバックアップ設定
- [ ] 最新Androidにおける通知権限とファイルアクセス
- [ ] edge-to-edge表示とシステムバー
- [ ] 予測型「戻る」操作

ターゲットAPI要件は毎年更新されるため、文書内の数値だけを前提にせず、提出時点の公式情報を確認します。

## 6. 健康アプリとしての申告

体重、身長、BMI、目標体重を扱うため、Google Playでは健康・フィットネス関連アプリとして扱われる可能性が高いです。

Play Consoleでは、健康アプリに関する申告フォームへの回答が必要です。

- [ ] Health apps declarationへ回答する
- [ ] 健康機能の目的を正確に説明する
- [ ] 体重などの情報の保存・利用・共有方法を説明する
- [ ] アプリ内とストア掲載情報にプライバシーポリシーを掲載する
- [ ] 診断、治療、医療効果を示す誤解のある表現を避ける
- [ ] BMIは一般的な目安であり、医療判断ではないと説明する
- [ ] 必要のない健康・センサー権限を要求しない

AndroidのHealth Connect連携は初回公開の必須機能にしません。追加する場合は、読み書きするデータ型、利用目的、同意、削除方法を明示し、Health Connect固有のポリシーへ対応します。

## 7. Data safetyとプライバシー

Google Playでは、Data safetyフォームにアプリおよび第三者SDKのデータ取扱いを申告します。

初回版では次の方針を推奨します。

- 体重、身長、性別、目標体重を端末内だけに保存する
- 開発者のサーバーへ送信しない
- 広告SDKと行動解析SDKを導入しない
- 不要な端末識別子を取得しない
- クラッシュ収集を導入する場合は送信内容を確認する
- バックアップや共有はユーザー操作時のみ行う

必要な対応は次のとおりです。

- [ ] 公開されたHTML形式のプライバシーポリシーを用意する
- [ ] Play ConsoleへプライバシーポリシーURLを登録する
- [ ] アプリ内からプライバシーポリシーを開けるようにする
- [ ] Data safetyへ正確に回答する
- [ ] 第三者SDKのデータ取扱いを確認する
- [ ] 保存期間と削除方法を説明する
- [ ] アカウントを追加する場合はアカウント削除方法を用意する
- [ ] 実装変更時にData safetyも更新する

端末内だけで処理する情報と、外部へ送信される情報は区別して申告します。Google Playの定義に基づき、実際のビルドを確認して回答します。

## 8. 権限

初回版では必要最小限の権限に限定します。

想定される権限は次のとおりです。

- 通知権限: 毎日の入力リマインダー
- ファイル選択: ユーザーがバックアップを読み込むとき
- ファイル作成または共有: ユーザーがバックアップや画像を保存するとき

Androidのシステムファイルピッカーと共有機能を利用し、端末ストレージ全体への広いアクセス権限は要求しません。

初回版では、位置情報、連絡先、カメラ、マイク、身体センサー、SMS、通話履歴などの権限を要求しない方針とします。

## 10. テスト要件

新しい個人開発者アカウントでは、本番公開を申請する前にクローズドテストが必要になる場合があります。対象となるアカウントでは、テスターが少なくとも14日間継続してテストへ参加する必要があります。必要人数や適用条件は、アカウント作成時と公開申請時のPlay Console表示を確認します。

準備事項は次のとおりです。

- [ ] テスターを募集する
- [ ] テスト参加用のGoogle Groupまたはメールリストを用意する
- [ ] テスト手順を用意する
- [ ] フィードバック窓口を用意する
- [ ] クローズドテストの必要期間を満たす
- [ ] 主要機能を実際に使用してもらう
- [ ] 公開申請時にテスト内容と改善点を説明できるようにする

- [ ] 画面サイズが異なる複数のスマートフォンで表示する
- [ ] 小型端末と大型端末で操作する

- [ ] アプリ終了後もデータが残る
- [ ] アプリ更新後もデータが残る
- [ ] アプリのデータ削除で記録が消える
- [ ] 通知許可と拒否の両方を確認する
- [ ] 通知チャンネルの名称と説明を確認する
- [ ] 機内モードで主要機能が動作する
- [ ] ファイルの保存、共有、読み込みを確認する
- [ ] 不正なバックアップでクラッシュしない

## 12. 将来の公開手順

1. Googleの開発者アカウントを登録し、本人確認を完了する
2. Package nameを決定する
3. Androidプロジェクトを生成する
4. Android固有の保存、共有、通知機能を設定する
5. リリース署名とPlay App Signingを設定する
6. Android App Bundleを作成する
7. Play Consoleにアプリを作成する
8. ストア掲載情報、Data safety、健康アプリ申告を入力する
9. 内部テストと必要なクローズドテストを行う
10. 本番公開へのアクセスを申請する
11. 審査へ提出する
12. 承認後に公開状態を確認する
