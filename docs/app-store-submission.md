# App Store 出品ガイド

最終確認日: 2026年9月29日

この文書は、`Yayoi-0108/weight-manager` を iPhone 向けアプリとして App Store に出品するために必要な作業と情報を整理したものです。

## 1. プロジェクト情報

| 項目 | 内容 |
| --- | --- |
| GitHubリポジトリ | `Yayoi-0108/weight-manager` |
| Gitリモート | `https://github.com/Yayoi-0108/weight-manager.git` |
| 公開ブランチ | `main` |
| 現在のWeb版 | `https://yayoi-0108.github.io/weight-manager/` |
| アプリの用途 | 毎日の体重、目標体重、身長、性別の記録とグラフ表示 |
| 現在の保存方法 | ブラウザの `localStorage` |
| アカウント機能 | なし |
| サーバー同期 | なし |

このプロジェクトでは、`pet-care-preview` その他のペットケア関連リポジトリ、URL、ファイルを使用しません。

## 2. 現在の状態

現在の実装は、`index.html`、Webアプリ用マニフェスト、画像で構成された静的Webアプリです。

すでに備わっている主な機能は次のとおりです。

- 今日の体重の記録
- 目標体重の設定
- 身長と性別の設定
- BMIの表示
- 1週間、1か月、1年のグラフ
- カレンダーから過去の記録を編集・削除
- JSON形式のバックアップと復元
- ホーム画面の画像共有
- 端末内データのリセット

ただし、Webアプリのファイルや `manifest.webmanifest` だけをApp Storeへ提出することはできません。iOSアプリとしてビルド、署名、アップロードできるXcodeプロジェクトが必要です。

## 3. 推奨するiOSアプリ化方針

### 初回公開の推奨方針

現在のHTML、CSS、JavaScriptを活用し、Capacitorなどを使ってiOSアプリ内に同梱する方式を推奨します。この方式では、同じWeb資産からAndroidプロジェクトも生成できるため、将来のGoogle Play出品にも対応しやすくなります。

ただし、公開中のWebページをそのままWebViewで表示するだけのアプリにはしません。Appleの審査では、単なるWebサイトの再パッケージではなく、十分な実用性とアプリらしい体験が求められます。

初回公開までに、少なくとも次の対応を行います。

- [ ] HTML、JavaScript、CSS、画像をアプリ本体に同梱する
- [ ] オフラインでも主要機能を利用できるようにする
- [ ] CDNから読み込んでいる `html2canvas` をアプリ内に同梱する
- [ ] iOSの共有シートを使って画像やバックアップを共有する
- [ ] 毎日の入力リマインダーをローカル通知で提供する
- [ ] iOSのセーフエリアに対応する
- [ ] VoiceOver、文字サイズ、コントラスト、タップ領域を確認する
- [ ] アップデート後も記録データが保持されることを確認する
- [ ] 通信できない環境でも起動できることを確認する

### データ保存

WebView内の `localStorage` のままでも動作する可能性はありますが、大切な体重記録を扱うため、iOSアプリでは永続性が明確な保存方式へ移行することを推奨します。

候補は次のとおりです。

- Capacitorのネイティブストレージプラグイン
- SQLite
- SwiftUIへ移行する場合はSwiftDataまたはCore Data

既存ユーザーのWeb版データは自動ではiOSアプリへ移りません。JSONの「データを保存」「データを読み出し」機能を移行手段として維持します。

### 初回公開では必須にしない機能

次の機能はアプリらしさを高めますが、プライバシーや実装範囲が増えるため、初回公開後の追加でも構いません。

- HealthKitとの体重同期
- ホーム画面ウィジェット
- iCloud同期
- Apple Accountなどを使ったログイン
- 複数端末間の同期

HealthKitを追加する場合は、健康データの用途、権限説明、App Storeのプライバシー申告を改めて確認します。

### 将来のGoogle Play出品を考慮した構成

このプロジェクトは、将来的なGoogle Play出品も想定します。初回のiOS対応で、iOSにしか使えない形へWeb側の主要ロジックを書き換えないようにします。

推奨構成は次のとおりです。

```text
共通Webアプリ
├── 画面とスタイル
├── 体重・BMI・グラフの処理
├── 入力値の検証
└── バックアップ形式
    ├── iOS用ネイティブプロジェクト
    └── Android用ネイティブプロジェクト
```

次の機能は、共通インターフェースを介して各OSの実装を呼び出します。

- データの永続保存
- ファイルの保存と読み込み
- 画像共有
- ローカル通知
- 外部URLの表示
- 権限の確認と要求

プライバシーポリシー、データ削除方法、バックアップのJSON形式も、可能な限りiOS版とAndroid版で共通化します。Google Play固有の準備については [`google-play-submission.md`](google-play-submission.md) を参照してください。

## 6. プライバシーと健康情報

### 基本方針

初回版では、体重、身長、性別、目標体重を端末内だけに保存し、開発者のサーバーには送信しない構成を推奨します。

この構成で、解析SDK、広告SDK、クラッシュ収集SDKなども使用しない場合、App Store ConnectのApp Privacyでは「このアプリからデータを収集しない」と回答できる可能性があります。ただし、実際のアプリとすべての第三者ライブラリの挙動を確認してから回答します。

Appleの定義では、端末内でのみ処理され、開発者や第三者へ送信されない情報と、外部へ送信される情報を区別する必要があります。

### 必須対応

- [ ] 公開されたプライバシーポリシーを作る
- [ ] App Store ConnectにプライバシーポリシーURLを登録する
- [ ] アプリ内の設定画面からプライバシーポリシーを開けるようにする
- [ ] 収集する情報、利用目的、第三者提供の有無を明記する
- [ ] 保存場所と保存期間を明記する
- [ ] データを削除する方法を明記する
- [ ] バックアップを書き出すと端末外に保存されることを説明する
- [ ] 第三者ライブラリの通信とデータ取扱いを確認する
- [ ] App Store ConnectのApp Privacyへ正確に回答する

アカウントを作成しない現在の設計では、オンラインアカウントの削除機能は不要です。将来アカウント作成機能を追加する場合は、アプリ内からアカウント削除を開始できる機能が必要になります。

### BMI表示に関する注意

このアプリのBMI表示は、診断、治療、医療上の判断を行う機能として表現しません。

アプリ内のヘルプや説明文には、次の趣旨を掲載します。

> 本アプリのBMIおよび体重に関する表示は、日々の記録を補助するための一般的な目安です。診断や治療を目的とするものではありません。健康上の判断が必要な場合は、医師などの専門家に相談してください。

医学的な効果、減量効果、正確性を保証する表現は使用しません。

## 12. App Review向け説明

審査メモには、審査担当者が主要機能を迷わず確認できるように記載します。

例:

> このアプリは、毎日の体重を端末内に記録し、グラフとカレンダーで振り返るためのアプリです。ユーザー登録やログインはありません。入力した体重、身長、性別、目標体重は端末内にのみ保存され、開発者のサーバーへ送信されません。設定画面からJSON形式のバックアップ作成、復元、全データ削除を行えます。ローカル通知は入力リマインダーにのみ使用し、許可しなくても主要機能を利用できます。BMI表示は一般的な目安であり、診断または治療を目的としません。

## 14. 審査で特に注意する点

### 単なるWebサイトのラッパーにしない

AppleのApp Review Guidelines 4.2では、Webサイトを再パッケージしただけではない、十分な機能、コンテンツ、UIが求められています。オフライン動作、ネイティブ共有、通知、安定した端末内保存、iOSに合った操作性を提供します。

### 完成した状態で提出する

準備中の文言、動作しないボタン、空のページ、仮URLを残しません。審査前に実機でクラッシュと主要操作を確認します。

### メタデータを正確にする

スクリーンショット、説明文、プライバシー申告は、提出するビルドの実際の挙動と一致させます。

### 問い合わせ先を維持する

アプリ内とサポートURLの両方で、利用者が問い合わせできるようにします。

### 健康に関する誇張を避ける

体重やBMIを扱いますが、医療診断、治療、効果保証として表現しません。
